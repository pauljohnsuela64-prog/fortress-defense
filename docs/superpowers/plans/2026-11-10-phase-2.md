# Phase 2 implementation plan

Implement the user's Phase 2 specification on `feat/phase-2-towers-enemies`, preserving the approved Phase 1 baseline and existing Phaser/TypeScript boundaries. No dependencies, backend, external graphics, push or PR.

## Design

Use the existing Tower class with an archer/cannon/magic type and three centrally configured stat levels. Shared targeting, purchases and upgrades avoid three copies of the same logic. Projectiles snapshot firing stats; cannon impacts affect live enemies within a radius and create a short-lived visual explosion. Magic applies a non-stacking slow: stronger replaces weaker, equal refreshes, weaker cannot extend stronger; movement accounts for expiry within a time step. Normal, fast and tank enemies share movement with configurable stats and different procedural shapes.

Native HTML tower shop and upgrade buttons remain keyboard-accessible and support touch. Desktop uses a side panel; mobile stacks the controls below the battlefield. Selection distinguishes an existing tower from a build preview. DOM controls only refresh when their displayed state changes. Restart clears selection, entities, effects and listeners.

## Tasks and scope

1. Verify clean branch and baseline; run existing type checks, tests and build (passed before edits). Extend tracked `.gitignore` for secrets.
2. Add tests first in `tests/phase2.test.ts`: each type's purchase price, failed purchases, level cap, insufficient funds, upgrade stats, projectile stat snapshot, splash boundaries and duplicate settlement, slow refresh/expiry, wave compositions and fresh-state reset. Preserve and adapt `tests/game.test.ts` to configurable types. Watch new tests fail, then implement.

Update `GameConfig`, `Tower`, `Projectile`, `Enemy`, `WaveManager`, and `GameState`. `placeTower(column,row,type)` and `upgradeTower(tower)` validate centrally; `Projectile.update(seconds,enemies)` returns an optional explosion; `Enemy.slow(factor,duration)` and `Tower.stats` hold effect and level behavior.
4. Update `GameScene`, `index.html`, `style.css`, and browser smoke assertions. Extract procedural entity rendering to `src/rendering.ts` to keep input/UI separate from drawing. Test all shop buttons, upgrades, keyboard selection, touch placement, restart, combat and responsive layouts in Chrome.
5. Run full-game victory/defeat simulations, TypeScript, Vitest, production build, audit and browser smoke. Review screenshots and request independent code review. Update README and commit locally.

## Review focus

- Failed purchases/upgrades and max-level requests never spend gold.
- Splash and simultaneous projectiles settle each death only once; escaped enemies never pay rewards.
- Slow expires exactly, including partial frames; repeat hits do not multiply slow factors.
- Restart during combat clears upgraded towers, projectiles, visual effects, selection and listeners.
- Shop remains usable at mobile widths; canvas touch should not scroll while placing, and panel taps never place towers.
